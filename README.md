# Let's meet!

Сервис для организации частных и публичных встреч: организатор за минуту создаёт страницу встречи, гости подтверждают участие одним нажатием, без регистрации и установки. Работает как сайт и как PWA (ставится на экран телефона).

**Стек:** Next.js 14 (App Router) · TypeScript · Tailwind CSS · Supabase (PostgreSQL, Auth) · PWA. Стиль: Playful.

## Что уже работает

| Раздел | Адрес | Что делает |
|---|---|---|
| Лендинг | `/` | Описание сервиса, кнопки создания и примера |
| Демо-встреча | `/e/demo` | Работает без базы данных, ответы живут только в браузере |
| Приглашение | `/e/<slug>` | RSVP «Приду / Думаю / Не смогу», время и место, ссылка на карту (2GIS), «Добавить в календарь» (.ics), дресс-код, сбор денег с переводом на Kaspi и списком «кто сколько внёс», «кто что принесёт» |
| Вход организатора | `/login` | Вход по ссылке на почту (без пароля) |
| Создание встречи | `/new` | Форма и ИИ-помощник: одна фраза заполняет поля |
| Мои встречи | `/dashboard` | Список встреч организатора |
| Панель организатора | `/dashboard/<slug>` | Счётчики ответов, список гостей с фильтром, ссылка и напоминание, подтверждение и отклонение взносов, ручной взнос, реквизиты Kaspi, управление списком «что принести» |
| ИИ-помощник | `POST /api/ai/draft` | Claude API; без ключа работает простой разбор фразы |
| PWA | `manifest`, `public/sw.js` | Установка на экран, офлайн-доступ к уже открытым страницам |

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
cp .env.example .env.local     # впиши ключи, см. ниже
npm run dev                    # http://localhost:3000
```

Без `.env.local` сайт запустится, лендинг и `/e/demo` будут работать, а остальные страницы покажут подсказку про настройку базы.

### 1. База данных (Supabase)

1. Создай проект на supabase.com.
2. Открой **SQL Editor → New query**, вставь содержимое `supabase/migrations/0001_init.sql` и нажми **Run**. Затем так же выполни `supabase/migrations/0002_kaspi_contributions.sql` (реквизиты Kaspi и список взносов).
3. В **Project Settings → API** скопируй `Project URL` и `anon public key` в `.env.local`:
   `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. В **Authentication → URL Configuration** добавь в Redirect URLs: `http://localhost:3000/auth/callback` (и адрес боевого сайта, когда он появится).

### 2. ИИ-помощник (необязательно)

Впиши `ANTHROPIC_API_KEY` в `.env.local`. Модель задаётся в `ANTHROPIC_MODEL`. Ключ используется только на сервере, в браузер он не попадает. Без ключа кнопка «Заполнить с ИИ» работает по ключевым словам (тип встречи, день недели, время, дресс-код).

### 3. Публичный адрес

`NEXT_PUBLIC_SITE_URL` нужен для ссылок-приглашений. Локально `http://localhost:3000`.

```

    page.tsx                 лендинг
    e/[slug]/                приглашение (page.tsx — сервер, InviteClient.tsx — RSVP и действия гостя)
    new/                     создание встречи
    dashboard/               список встреч и панель организатора
    login/, auth/            вход по почте, callback, выход
    api/ai/draft/route.ts    ИИ-помощник
    manifest.ts              PWA-манифест
  components/                Logo, SiteHeader, SetupNotice, ServiceWorkerRegister
  lib/
    supabase/                клиенты для браузера и сервера
    format.ts                даты (Алматы), деньги, slug, ссылка на 2GIS
    demo.ts                  демо-встреча
    guest.ts                 анонимный ключ гостя (localStorage)
  middleware.ts              обновление сессии организатора

public/sw.js                 service worker
```

### Модель доступа

- **Гости без аккаунта.** Они не читают и не пишут в таблицы напрямую. Всё идёт через функции в базе (`get_event_public`, `submit_rsvp`, `claim_item`, `release_item`, `add_pledge`, `cancel_pledge`). Гостю присваивается анонимный ключ в браузере: по нему он меняет свой ответ. Чужие ключи наружу не отдаются.
- **Организатор** (вошёл по почте) видит и меняет только свои встречи, гостей и переводы: это обеспечивают политики RLS.
- Встречи «По ссылке» нельзя найти перебором: они не отдаются списком, только по точному адресу. Публичные видны всем.

## Что сознательно не сделано

- **Автоматический приём денег.** Сервис деньги не проводит и не видит поступлений в Kaspi: у Kaspi нет интерфейса, через который сайт мог бы сам проверить перевод на личный номер. Поэтому так: организатор указывает свой номер Kaspi, гость переводит сам и нажимает «Я отправил», взнос появляется со статусом «Ждёт подтверждения», организатор сверяет его с поступлением в приложении Kaspi и нажимает «Деньги получил». Только после этого сумма входит в «Собрано». Автоматическое подтверждение возможно лишь через платёжный шлюз для бизнеса (Kaspi Pay, CloudPayments): нужен договор с юрлицом или ИП.
- **Push-уведомления и рассылки.** У сервиса нет контактов гостей, поэтому напоминание организатор отправляет сам через кнопку «Поделиться напоминанием» (системное окно «Поделиться» на телефоне, на компьютере копируется текст).
- **Защита от спама в ответах.** Нет ограничения частоты запросов и капчи. Для боевого запуска стоит добавить (например, через Cloudflare Turnstile или лимиты Supabase).
- **Карта внутри страницы.** Вместо встроенной карты кнопка «Открыть на карте» ведёт в 2GIS по названию и адресу.
- **Тесты.** Автотестов пока нет, проверялись сборка, типы и сценарии демо-страницы.

## Дальше

1. **Android и iOS.** Обернуть сайт в Capacitor: `npm i @capacitor/core @capacitor/cli`, `npx cap init`, указать `server.url` боевого сайта, `npx cap add android`. Для App Store нужны Mac или облачная сборка и аккаунт Apple Developer; Apple часто отклоняет «голые» обёртки, поэтому добавь нативные функции (push, календарь, шеринг).
2. **Деплой.** Vercel (проще всего): подключить репозиторий, добавить переменные из `.env.example`.
3. **Языки.** Интерфейс сейчас на русском; казахский и английский добавляются через i18n (например, `next-intl`).
